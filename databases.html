Narrative

Artifact Description

The artifact I selected for this enhancement is my Android Inventory Management Application originally created in CS 360. The application stores inventory information using a SQLite database and allows users to manage inventory through a mobile interface. For this milestone, I focused on expanding the database functionality beyond basic CRUD operations.

Justification for Inclusion

I selected this artifact because database functionality is a major component of inventory management systems. The original application stored inventory quantities but did not maintain historical records or provide reporting capabilities. This enhancement allowed me to demonstrate database design, reporting, and data analysis skills while improving the usefulness of the application.

Enhancement Overview

The primary enhancement was the creation of a usage_history table. Whenever inventory is picked, the application now stores information such as part number, quantity used, ticket number, and transaction date. This creates a permanent historical record of inventory activity instead of only updating current inventory quantities.

I also implemented a Usage Report feature that allows users to review inventory activity during selected date ranges. In addition, I created a Top Used Parts Report that identifies the most frequently used inventory items based on historical records.

Database Design and Reporting

The usage_history table provides a relationship between current inventory records and historical transactions. This design allows the application to maintain accurate inventory quantities while also supporting long-term reporting and analysis.

The reporting features use aggregate database queries such as COUNT and SUM to calculate usage statistics and summarize inventory activity. These queries transform raw data into meaningful business information that supports decision-making.

Course Outcome Alignment

This enhancement demonstrates database design, data organization, reporting, and analysis skills. It also aligns with the Computer Science program outcome focused on implementing computing solutions that deliver value through effective use of data. The application now provides meaningful information beyond simple inventory storage by supporting historical tracking and reporting capabilities.

Challenges and Testing

One challenge was ensuring that inventory quantities and usage history records remained synchronized. Whenever inventory was picked, both the inventory table and the usage_history table needed to update correctly. Careful testing was required to ensure data consistency.

Testing included verifying quantity updates, creation of history records, report generation, date filtering, and Top Used Parts calculations. I confirmed that inventory quantities remained accurate while usage history continued to capture all transactions correctly.

Reflection

This enhancement helped me better understand how databases support real-world business applications. The application now stores historical inventory activity, generates reports, summarizes usage information, and provides more value to users than the original version. This project reinforced the importance of database design and demonstrated how data can be transformed into useful information for decision-making.
