Enhancement Summary

This enhancement focused on expanding the database from basic inventory storage into a system that tracks historical usage and generates reports.

  • Added a usage_history table
  • Tracked inventory usage over time
  • Added Usage Report functionality
  • Added Top Used Parts reporting
  • Used aggregate queries such as COUNT and SUM

Narrative

Database Enhancement Narrative Artifact Description The artifact I selected for this enhancement is my Android Inventory Application, which was originally created in CS 360. The purpose of the application is to help users manage inventory by adding, editing, deleting, and tracking inventory items through a mobile interface. The application stores inventory information in a local SQLite database so data is saved even after the application is closed. I selected this artifact because it already relied heavily on a database and provided a good opportunity to demonstrate database design and development skills. Since inventory management systems depend on storing, retrieving, and organizing data efficiently, I felt this project was a strong choice for the database enhancement category of my ePortfolio. Enhancement Overview For this enhancement, I expanded the database functionality of the application by adding inventory usage tracking and reporting features. In the original version of the application, users could add, edit, and remove inventory items, but there was no way to track how inventory was being used over time. Once a quantity changed, there was no history available to show what happened. To improve this functionality, I created a new database table called usage_history. This table stores information whenever inventory is picked, including the item information, quantity used, RMA or ticket number, and the date the transaction occurred. This allows the application to maintain historical records instead of only storing the current inventory quantity. The usage_history table creates a relationship between inventory records and historical inventory transactions. Each time inventory is picked, a corresponding usage record is created while the inventory quantity is updated. This design allows the application to maintain both current inventory levels and historical activity without losing information. Maintaining separate tables for inventory and usage history improves organization and supports future reporting needs. I also added a Usage Report feature that retrieves information from the database and displays a history of inventory usage. I enhanced the reporting functionality by adding summary statistics that display the total number of usage records and the total quantity of parts that have been picked. To further improve the reporting capabilities, I created a Top Used Parts report. This report uses aggregate database queries to summarize inventory usage and identify which parts are used most often. The report organizes the data and displays parts based on the total quantity picked. The reporting features rely on aggregate database queries such as COUNT and SUM to calculate summary statistics and identify frequently used inventory items. These queries allow the application to transform raw transaction data into meaningful information that can support inventory planning and decision making. These enhancements transformed the database from a simple storage solution into a tool that can be used to track inventory activity and generate useful reports.
